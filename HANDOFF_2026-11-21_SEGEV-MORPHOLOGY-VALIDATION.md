## Root cause found — missing immediately branching axon attachment

Latest geometry run [44886628293](https://github.com/Nolane-x/Nghien-cuu/actions/runs/44886628293) shows NMO_68175's NEURON total area is 83,861.8731579 µm² while AMSN is 84,538.3504114 µm², a difference of 676.4772535 µm² (−0.8002016%). The SWC edge from soma root 1 to axon node 5851 has a frustum area of 676.4765820 µm² and length 12.06765097 µm. NEURON's imported axon path is 676.4514768 µm versus 688.5191355 µm from SWC, again omitting that exact first edge to within 8e−6 µm.

Node 5851 is a direct root child and immediately branches (two children). The previous detector only marked first neurite nodes with more than one unbranched same-type edge, so it missed this axon attachment. The normalizer now treats every direct non-soma child of a verified three-point soma as an attachment, preserving the later SWC edges. The physical passive constants are unchanged. The next four-job matrix rerun must confirm area agreement and lower low-frequency impedance errors.

## Import3D normalizer edge-case correction

The first attempt to collapse all direct neurite roots was rejected by Core CI: a synthetic one-point terminal neurite attached to a three-point soma was incorrectly removed. The detector is now narrower: it collapses established long unbranched stems plus first neurite nodes that are immediate branch junctions (two or more children); it preserves a lone terminal neurite. This still captures Segev cell1204 axon node 5851 and has an explicit negative regression test.

## Verified Import3D soma-attachment fix — final results (commit f63b3ce)

**Status:** resolved for the tested Import3D soma convention on both Segev morphologies; 4/4 multi-morphology jobs passed. Core CI also passed 4/4 jobs, including 81 tests on Python 3.12 and 81 on Python 3.13.

### Root cause and narrow correction

At NMO_68175, SWC node 5851 is a direct soma child of type axon and immediately branches into two children. The old detector only collapsed first neurite roots that continued as a long unbranched same-type stem, so it missed 5851. The NEURON importer did not retain the soma-centre-to-node-5851 edge as cable geometry. That edge has SWC frustum area 676.4765820 µm² and length 12.06765097 µm; this matched the pre-fix NEURON-versus-AMSN area residual (676.4772535 µm²) and axonal path-length difference (~12.06766 µm).

The final rule collapses (a) established long unbranched soma stems and (b) first neurite points that are themselves branch junctions (two or more children). A one-point terminal neurite is retained. The first attempt that collapsed every direct soma child was rejected by Core CI because it removed a synthetic terminal edge; this negative result is preserved in the source tests and handoff.

## Source-placement nseg-cap failure and bounded redesign

The first Segev source-placement run [44888178565](https://github.com/Nolane-x/Nghien-cuu/actions/runs/44888178565) verified both SWC files and passed 81 tests in each job, but failed during local refinement: it could not create distinct legacy and SWC-aligned centres within 0.002 µm under NEURON's 32,767 nseg per-section cap. This is not a morphology/test failure.

The source-placement algorithm was revised to search candidate odd nseg values up to the hard cap, map the old legacy source coordinate to its nearest centre on the chosen shared mesh, and map the SWC coordinate to a different centre. The legacy coordinate remapping is explicitly recorded; the two modes still differ only in IClamp segment on an identical mesh. New diagnostics report the best achievable SWC-centre offset if the tolerance cannot be met. Validate the new algorithm with Core CI, then rerun both Segev cells. Keep failed runs documented.


## Placement-control edge case: pre-aligned source

The first bounded nseg rerun found that NMO_68174 dend[26] is already at its SWC target to 1.535e-7 µm. The control now reports already_aligned=true and preserves the same segment in both modes for that source, rather than constructing an artificial perturbation. For other sources it searches for two distinct centres on a shared mesh. Confirm the rerun output before interpreting source-placement sensitivity.


## Pre-aligned source handling under the NEURON nseg cap

NMO_68174 `dend[26]` and NMO_68175 `apic[20]` can have the original legacy centre and exact SWC coordinate resolve to the same segment even at NEURON's 32,767 nseg cap. The control now records `already_aligned=true` and preserves that segment when its centre is within 0.05 µm of the SWC target (`AMSN_SOURCE_ALREADY_ALIGNED_MAX_OFFSET_UM`). This is distinct from the 0.002 µm target tolerance used when a distinct SWC-aligned centre is constructible. A source farther than 0.05 µm still fails clearly. Inspect the output metadata and raw CSV to identify which source rows are genuine placement changes; do not infer a placement effect for a pre-aligned source where the two modes are identical.

## Correction: prior Segev placement output was not a sensitivity comparison

Artifacts from workflow 44888621661 show both modes used the same segment for all four Segev source sites: the broad 0.05 µm fallback labelled them all pre-aligned. These data must not be used to claim a placement effect. They only record source-centre offsets and expose the nseg cap.

The updated control distinguishes `pre_aligned` (strict ≤0.002 µm), `distinct_aligned` (different segment centre on the same mesh, SWC centre ≤0.002 µm), and `unresolved_nseg_cap` (cannot separate under the cap; keep the legacy segment and record best achievable offset). The raw CSV includes alignment status and best possible offset. Do not interpret unresolved rows as aligned or as evidence of reduced error.
